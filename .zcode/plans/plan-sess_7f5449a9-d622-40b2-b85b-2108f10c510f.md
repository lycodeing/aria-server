## C1 + C2 DDD 层次修复计划

### C1：SlaPolicyMatcher domain层不依赖infrastructure层

**新建文件：** `domain/service/SlaPolicyRepository.java`
```java
package com.aria.conversation.domain.service;

import com.aria.conversation.infrastructure.persistence.entity.SlaPolicyEntity;
import java.util.List;

/**
 * SLA 策略仓储接口（domain 层）。
 * 由 infrastructure.cache.SlaPolicyCache 实现，
 * 通过依赖倒置保持 domain 层不依赖 infrastructure。
 */
public interface SlaPolicyRepository {
    List<SlaPolicyEntity> findAllEnabled();
}
```

**修改：** `infrastructure/cache/SlaPolicyCache.java`
- 类声明改为 `implements SlaPolicyRepository`
- 新增 `findAllEnabled()` 方法（委托现有 `getAllEnabled()` 逻辑，或直接重命名）
- `evict()` 不变（Controller 仍可直接调用）

**修改：** `domain/service/SlaPolicyMatcher.java`
- 字段类型：`SlaPolicyCache` → `SlaPolicyRepository`
- 调用：`slaPolicyCache.getAllEnabled()` → `slaPolicyRepository.findAllEnabled()`
- 删除 `import com.aria.conversation.infrastructure.cache.SlaPolicyCache`

### C2：TagAdminController 不绕过 application 层

**修改：** `application/service/TagAppService.java` — 新增 4 个标签字典管理方法

```java
// 列表（可按 source 过滤，按 name ASC 排序）
public List<TagEntity> listTags(String source)

// 新建 PRESET 标签；重名抛 BusinessException(40900, "标签名已存在")
@Transactional(rollbackFor = Exception.class)
public TagEntity createPresetTag(String name, String color)

// 修改（name/color/source）；不存在抛 BusinessException(40400, "标签不存在")
@Transactional(rollbackFor = Exception.class)
public void updateTag(Long id, String name, String color, String source)

// 删除（前端已二次确认 usage_count>0，后端直接删除）
@Transactional(rollbackFor = Exception.class)
public void deleteTag(Long id)
```

**修改：** `interfaces/rest/TagAdminController.java`
- 移除 `TagMapper tagMapper` 字段
- 新增 `TagAppService tagAppService` 字段（通过 `@RequiredArgsConstructor` 注入）
- 4 个端点处理器全部改为 `tagAppService.xxx()` 委托调用
- 业务异常（CONFLICT=40900、NOT_FOUND=40400）由 Service 层抛出，Controller 不再持有错误码常量

**变更范围：** 5 个文件（新建 1 + 修改 4），所有对外 API 接口不变。
